## ⚡ Common Patterns

**Code Style (Biome enforced):**
- TypeScript strict mode
- ES6+ features (async/await, destructuring)
- No semicolons (ASI)
- 2-space indentation, single quotes
- 100-char line width

**API Design:**
- Canonical response format (V3 OpenAPI at `/v3/openapi.json`)
- RFC 9457 Problem Details for errors
- ZERO direct client API calls
- Multi-provider orchestration with circuit breakers

**Data Layer:**
- `BookRepository` - Abstraction over KV + D1
- Dual-write: KV + D1 for durability
- `D1_READ_PERCENTAGE` controls read routing (0-100%)
- `BookService` - High-level data access

**Async Jobs:**
- Cloudflare Workflows for stateful operations
- Queues for async enrichment/cover processing
- Durable Objects for real-time progress

**Circuit Breaker:**
- Per-provider circuits (alexandria, google-books, open-library, isbndb)
- 5 failures → OPEN, 2 successes → CLOSED, 60s cooldown
- KV-backed state with 5min TTL
- Analytics logging for observability

**Cache Architecture (v3.0 - Alexandria-First):**
- **Primary Provider:** Alexandria RPC v2.8.0 (49M+ ISBNs, internal data, <100ms)
- **KV Cache:** Book metadata with 2h hot / 14d cold TTL
- **Service Binding:** Sub-millisecond RPC when available
- **Provider Chain:** Alexandria → Google Books → OpenLibrary
- **New in v2.8.0:** Analytics tracking utilities, improved orchestration

**Testing (Dual Pool):**
- **Workers Pool:** Smoke tests, pure utilities (runs in workerd)
- **Node Pool:** Unit tests, integration tests (supports vi.spyOn)
- Resource-aware: `test:smoke` (5s), `test:safe` (512MB limit)
